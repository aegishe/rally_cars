# ADR 0001：选择纯增程电四驱作为完美越野架构

## 状态

已决定

_追记（2026-08）_：本 ADR 的"纯增程电四驱"决策适用于**标准版/长轴版**。激进后置版（CONTEXT 版本表第三版）偏离纯增程路线——发动机经行星齿轮 4 档动力分流直驱后轮+发电供前桥，属功率分流架构（THS 路线的纵置后驱化）；其目的是补纯增程"无机械直驱=单点失效"的硬伤，作为演进变体单列，不改本 ADR 的主线决定。

## 上下文

现有混动越野架构在 2026 环塔拉力赛 9 个赛段中暴露了各自的物理短板：

- **P2 并联（Hi4-T）**：亏电不掉底（发动机直驱），但变速箱体积锁死 P2 电机尺寸，短冲刺爆发力不足，且 P2 发电功率受限于发动机转速耦合
- **DMO/单档混动**：满电爆发力极强（攀爬甜点），但亏电后全线依赖 P1 发电，P1 持续仅 91kW（豹 5），沙漠长耐力断崖掉速
- **多档 DHT（Hi4-Z）**：有直驱档位兼顾效率和爆发力，但换挡逻辑不适合竞技越野（多档位在沙丘/戈壁间的切换决策复杂），且 2026 环塔 SS5 有 Hi4-Z 因保电+散热退赛。民用场景已有旁证——坦克 500 Hi4-Z 实测 0-100 纯电模式快于运动模式（混动），换挡延迟的时间成本连直线加速都抹不掉
- **纯增程（奥迪 RS Q e-tron）**：达喀尔冠军，证明纯增程+大发电机+轻量化是可行的，但赛车级的碳纤维车体和 35kg/250kW 电机无法直接复制到民用

核心矛盾：**"上限高"（大电机爆发力）和"下限高"（亏电不掉底）在现有民用架构中不可兼得。**

## 决定

采用**纯增程电四驱**作为完美架构的拓扑基础：

1. 发动机**不通过任何机械路径连接车轮**，仅驱动 P1 发电机
2. 前后桥各由独立电机驱动（P3 前桥 + P4 后桥），无传动轴
3. 前后桥配备机械限滑差速器（LSD），轴间扭矩分配由虚拟中央差速器软件完成
4. 增程器为特化 2.0T 发动机（200kW 持续，4000-5500rpm 窄带，全附件电气化）
5. P1 发电机目标持续 190kW 电功率

## 替代方案

### P2 并联改进型（保留变速箱+传动轴，加大电机）
- **优势**：亏电机械直驱不变，下限已证
- **拒绝原因**：P2 电机径向尺寸被变速箱壳体锁死，无法显著加大；P2 发电功率耦合于发动机转速，低速发电效率低——两个物理约束无法在 P2 框架内解决

### 行星齿轮功率分流（丰田 THS 路线）
- **优势**：发动机转速解耦，可兼顾发电效率和直驱
- **拒绝原因**：THS 本质是横置前驱，后桥只能靠 P4 电驱，仍然面临亏电后桥崩塌风险。越野场景的机械四驱需求与 THS 的横置基因矛盾

### 多档 DHT + 大 P1（Hi4-Z 增强版）
- **优势**：有直驱档，高速效率好
- **拒绝原因**：多档 DHT 在沙丘/戈壁等扭矩剧烈变化的场景下，换挡逻辑容易出错，竞技可靠性不足。砍掉 DHT 释放了变速箱重量和复杂度，省下的空间/重量全部投入 P1 和散热

### 保留 DMO 单档 + 超大 P1
- **优势**：有单档直驱，高速省油
- **拒绝原因**：单档直驱在沙漠长耐力中几乎不参与（车速低、扭矩波动大，发动机无法锁在直驱档），本质仍是增程模式。与其带一个几乎不用的离合器，不如砍掉，简化系统

## 后果

### 正面
- P1 发电机不再受变速箱空间约束，可独立布置并配备专属散热，持续功率从民用级 60-91kW 跃升至 190kW
- 砍掉变速箱/分动箱/传动轴节省约 160kg，全部用于 P1/P4 和散热系统后净重不增
- 前后机械 LSD + 虚拟中央差速器兼顾了高速贴地性（全独立悬架）和脱困可靠性（不依赖电量）
- 持续功重比 68.8 W/kg，比坦克 400 Hi4-T（55.2）+25%，沙漠巡航不掉速
- 拓扑与达喀尔冠军车奥迪 RS Q e-tron 一致，路线已被最高级别赛事验证

### 负面
- 没有机械直驱路径，一旦 P1 或高压系统故障，全车瘫痪（P2 并联在电力系统失效后仍可纯发动机行驶）
- 190kW P1 持续电机目前无量产民用产品，需要定制或赛车技术下放（成本未知）
- 散热系统负担重——P1+P3+P4+发动机+电池五重热源，散热器面积和布置是工程挑战
- 前后机械 LSD 需要定期维护（换油、调间隙），比电子限滑的零维护门槛高
- 全独立悬架在极端抗冲击场景（如飞跳落地）相对后整体桥的可靠性待验证

### 中立
- 砍掉所有机械驱动路径后，整车 NVH 由发动机→P1→电驱的串联路径决定。发动机窄带 4000-5500rpm 运行可通过声学包和主动降噪处理，但这是额外的工程成本
- 三台独立 MGU（P1/P3/P4）的软件协同标定复杂度陡增——扭矩分配、动能回收、虚拟差速器的响应延迟都依赖软件成熟度

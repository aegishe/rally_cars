# 重采管道操作手册（抽帧→OCR→清洗→分析）

> 用途：把车载圈速视频转成高精度速度数据（默认 5fps），用于峰/谷定位、减速度、直道账等精细分析。
> 纯本机执行，零 token。已在本项目跑通（3 区段 × 2 车 = 485 帧）。
> 配套：`track/scripts/resample_config.json`（唯一需要改的配置）、`resample_all.ps1`（一键）、`resample_clean.py`（清洗）、`resample_analysis.py`（分析）

---

## 1. 常规工作流程（三步，flash 可执行）

**Step 1：改配置** `track/scripts/resample_config.json`
- 只在 `segments` 数组里增删区段，每项三字段：`car`（u9x/su7）、`name`（任意）、`frame_start`/`frame_end`（帧号）
- 帧号换算公式（重要）：
  - `frame_start = (t_manual − lap_offset) × 25`，其中 `t_manual` 是想要的手工口径时间（秒），`lap_offset` 见配置（u9x −2.00，su7 −2.08）
  - 帧号取 `fps_div`（=5）的整数倍
  - 例：要 su7 手工口径 256.0s 起 → (256.0 − (−2.08)) × 25 = 6452 ✓

**Step 2：一键跑管道**
```powershell
pwsh -File track\scripts\resample_all.ps1
```
每段输出一行 `car_segN : X 帧, OCR 完成`。帧数与预期不符会 Warning。

**Step 3：清洗 + 分析**
```powershell
$env:PYTHONIOENCODING="utf-8"; $env:PYTHONUTF8="1"
py -3.14 track\scripts\resample_clean.py     # 输出 track\u9x_5fps.csv / track\su7_5fps.csv
py -3.14 track\scripts\resample_analysis.py  # 峰谷 + 减速度对比表
```

**验收标准**（Step 3 输出里核对）：
- 有效率：直道段 >85%，弯道段 >65%（动态模糊所致，低于此值见分诊表）
- 峰谷速度与手工 1s 数据差 <10km/h；谷位置差 <0.5s
- 直道距离积分两车差 <1%（1874 vs 1878m 级别）

## 2. 全圈 5fps 重采（扩展模板）

把 `segments` 扩为全圈：按 60s 一段切成 8 段/车，帧号按下表（已按公式算好，u9x 视频 10588 帧、su7 10933 帧）：

| 段 | t_manual 区间 | u9x 帧 | su7 帧 |
|---|---|---|---|
| L1 | 0–60 | 50–1550 | 52–1552 |
| L2 | 60–120 | 1550–3050 | 1552–3052 |
| L3 | 120–180 | 3050–4550 | 3052–4552 |
| L4 | 180–240 | 4550–6050 | 4552–6052 |
| L5 | 240–300 | 6050–7550 | 6052–7552 |
| L6 | 300–360 | 7550–9050 | 7552–9052 |
| L7 | 360–420 | 9050–10550 | 9052–10552 |
| L8 | 420–437 | 10550–10588 | 10552–10933 |

（u9x 圈速段止于 419.2s；su7 止于 424.9s。L8 主要是尾部缓冲，可只抽到圈速结束。）
注意：L1–L8 会覆盖已抽的 seg1/2/3，重抽即覆盖，无冲突。总量约 2100 帧/车，OCR 约 2–4 小时。

## 3. 时间戳基准（实测确认，勿再猜测）

**手工数据时间戳 = 视频画面显示的 lap time，不是视频播放时间。**

| 车 | lap time 格式 | 显示粒度/刷新 | 首个有效帧 | 换算公式 |
|---|---|---|---|---|
| SU7 | `00:00.00`（两位小数 00-99） | **10Hz**（每次跳 10，即 0.1s 粒度） | 帧 52 = 00:00.02 | `lap = 帧号/25 − 2.06` |
| U9X | `00:00:00`（冒号分隔） | **25Hz**（每次跳 4，即帧级 0.04s） | 帧 57 = 00:00:04 | `lap = 帧号/25 − 2.24` |

推论：
- 手工 U9X 时间戳是帧级精确的（0.04s 分辨率）；手工 SU7 时间戳只有 0.1s 粒度（显示刷新限制）
- `lap_offset` 配置即上表换算中的常数（u9x −2.24、su7 −2.06，已实测标定）
- 若未来 OCR 能可靠读出 lap time 区域，可直接以 lap time 为时间戳、无需帧号推算（当前 time 区域 OCR 成功率低，属可选增强）

## 4. 已知坑清单（本管道已解决，勿再踩）

| # | 坑 | 已固化的解法 |
|---|---|---|
| 1 | batch-ocr 默认 `*.png`，jpg 被跳过 | 参数 `-Pattern "*.jpg"` |
| 2 | `-Detect` 输出坐标是原图坐标，但孤立数字区域 OCR 全空 | 区域必须**包含标签**（SPEED/GPS Speed），引擎需要上下文 |
| 3 | 按 `-ss`（PTS）抽帧与手工数据有 1–3s 漂移 | 改用 `trim=start_frame`（帧号口径）；YouTube 视频 PTS 与帧计数不可混用 |
| 4 | 两车视频前缓冲不同（u9x 2.24s / su7 2.06s，实测帧 57/52）导致整体偏移 | `lap_offset` 配置校准（u9x −2.24、su7 −2.06） |
| 5 | OCR 丢百位："210"读成"10"、"122"读成"022" | 清洗脚本连续性修复（+100/+200 候选，取最接近前一帧） |
| 6 | RMSE 校准值巨大（42–151）是采样相位差，非错误 | 忽略 RMSE，用峰谷特征验收（见 §1 验收标准） |
| 7 | 后台 job 环境：无 `pwsh` 7（用 `powershell.exe` 5.1）；**脚本参数传递不可靠**（`-Idx 0 -Total 8` 被吞 → 除零）；5.1 读 UTF-8 JSON 全角字符乱码 | 后台 OCR 用**硬编码命令**（每 job 命令内写死段名与路径，见 `ocr_shard.ps1` 与 8-job 模式）；抽帧放前台 pwsh 跑 |
| 8 | `Start-Process -ArgumentList` 数组拼接丢参数（全部进程跑同一段） | 弃用 Start-Process 传参；多进程并行一律用 job 硬编码命令 |
| 9 | 按命令行关键词杀进程会误杀自己（`CommandLine -match "batch_ocr"` 匹配到当前会话命令） | 过滤时加 `$_.ProcessId -ne $PID` |

## 5. 意外情况分诊表（flash 按表处置；表外问题切强模型）

| 现象 | 诊断 | 处置 |
|---|---|---|
| OCR 输出全 `- -` | 区域坐标/裁剪问题 | 跑 `-Detect` 复核坐标；确认区域含标签；确认 `-Pattern` 匹配 |
| 有效率 <50% | 弯道段动态模糊（物理问题） | `ocr_scale` 提到 5（已默认）；接受缺口；若关键峰谷帧缺失，单独补抽该 ±3s 区间 10fps |
| 速度序列整体偏移 ~2s | `lap_offset` 错 | 用 §3 公式复核：`lap_offset = 帧号/25 − lap_time`（取多个帧求均值） |
| 出现 10–96 连续假值 | OCR 丢百位"2" | 清洗脚本已修复；若仍出现，检查该帧原始 txt 行确认读数 |
| 峰/谷检测缺失 | 等值平台或窗口截断 | 确认窗口比目标 ±3s 宽；检测已放宽允许等值平台 |
| 抽帧数与预期不符 | trim 边界/视频帧数 | 核对视频 nb_frames（ffprobe），frame_end 勿超 |
| **表外异常**（新报错、数据形状诡异、结论与已知矛盾） | 未知 | **停止，切回强模型**。把异常输出 + 相关 txt/csv 片段 + 本手册路径贴给强模型会话，让其读 `track/CONTEXT.md` 和 `track/docs/SU7 Ultra纽北实测功率反推.md` 接上下文 |

## 6. 模型策略（2026-08 定案：全程 pro）

**决策：本项目全程使用强模型（v4-pro），不切 flash。** 理由：重采样本身零 token，清洗/解读的边际 token 已很低；pro 的异常兜底与数字一致性价值大于 flash 的成本优势。

本手册在全程 pro 下的用途：
- §1-2：工作流与全圈扩展模板（直接照做）
- §3-4：时间戳基准与坑清单（速查，避免重复踩坑）
- §5：分诊表降级为**诊断速查表**——pro 自己判断，表只是参考起点，不再有"表外停手切模型"的约束

切会话（重启/新开）后的接续方式不变：先读 `track/CONTEXT.md`（资产索引）→ `track/docs/SU7 Ultra纽北实测功率反推.md`（结论+待办）→ 本手册，3 个文件内接回全部上下文。
